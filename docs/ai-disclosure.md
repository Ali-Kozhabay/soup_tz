# AI assistance and review record

This repository was implemented with OpenAI Codex assistance, at the applicant's request. The agent read the supplied PDF, wrote the design note before the implementation, generated the service, migration, tests, harness, and documentation, and ran the local checks. **The repository does not assert that the applicant personally wrote or independently verified this code.** The applicant should review it before submission and describe their own review accurately.

Accepted design choices were PostgreSQL as the durable authority, Redis as disposable wake-up hints, short async SQLAlchemy transactions, row-lock serialization, fencing tokens, canonical-payload idempotency, and an effect row committed with success. Primary documentation links are recorded in the design note. Tests use real database/process behavior rather than mock-only claims.

The initial AI-generated chaos harness produced a misleadingly reassuring pass: it killed 32 workers but recorded zero expired attempts. Inspection showed that its oldest-running-job cancellation policy cancelled dead workers' jobs before recovery could occur. That run is retained unchanged. The harness was revised to preserve observed crash victims, choose live cancellation targets randomly, and require actual lease-recovery evidence in a full run. The later runs and their exact source snapshots show the change. No failed or inconvenient harness output was removed.

A later chaos run failed with an HTTP read error; the agent preserved it and recovered its committed jobs in a separate recorded operation, without claiming a proven cause. An initial sandbox-blocked load invocation is also retained. The 100-create-requests/sec measurements showed that four workers could accept requests quickly while falling behind; the Compose default was changed to eight after the eight-worker measurement kept up. Docker startup itself was not verified because the daemon was stopped.

Other checks performed by the agent include concurrent-key and claim tests, cancel/complete races, rollback between effect insertion and success, a real stopped/resumed worker, strict type checking, formatting/lint checks, migration creation, and an offered-load experiment. The evidence report distinguishes checks that ran from configuration provided for future CI.

At the applicant's request, Codex subsequently reorganized the code using the supplied FastAPI reference: feature routers/schemas in `src/api/web`, application services, core DTOs/interfaces, infrastructure adapters and repositories, and `src/main.py` beside `src/config.py`. The old monolithic API module was split into routers, dependencies, middleware, and exception handlers. The OpenAPI schema was compared with the pre-refactor snapshot and matched exactly. Historical experiment directories retain the original source layouts used for those runs; follow-up verification is recorded separately.

## Reflection on the experiment

The surprising result was that a correct-looking chaos run could avoid the recovery path entirely: cancellation made the crashed jobs terminal, so no invariant failed and no lease was reclaimed. Requiring a mechanism to have actually occurred made the evidence more useful. The remaining concerns are the narrow side-effect boundary, the finite and local nature of the experiments, and the difference between accepting 100 HTTP requests per second and keeping up with real training workloads. These are observations from this AI-assisted implementation, not a prewritten account of the applicant's personal experience or answers for the live discussion.
